# 活动操作

## 制定当期活动计划

长流程开始前记录以下字段：

- 活动名称、日期与版本；
- 用户要求的范围和完成定义；
- 章节与难度的解锁关系；
- 每个目标入口和路线约束；
- 首领或地图血条机制；
- 计划舰队、装备与战况中心增益；
- 题库和攻略来源及其更新时间；
- 宝箱、奖励、功勋或成就，以及分数阈值。

路线随活动而变化。当前游戏内的条件显示和实际走向一致之前，攻略建议都只是待验证假设。

## 把攻略转换成舰队约束表

每条路线都记录：

| 字段 | 需要记录的内容 |
|---|---|
| 入口 | `α`、`β` 或其他出击前入口 |
| 旗舰 | 1 号位要求的精确舰船或舰种 |
| 数量 | 按舰种或国籍规定的精确值、最小值或最大值 |
| 航速与索敌 | 最低、最高、平均或总值阈值 |
| 优先级 | 多个条件同时满足时哪项先判定 |
| 随机性 | 第一段或其他分支是否需要退出重来或撤退 |
| 目的地 | 预期首领、支援或宝箱节点 |
| 解锁 | 清除该节点后会开放什么 |

出击前用这张表核验完成后的准备页。

## 选择舰船

1. 规划换船顺序时，先释放已经在舰队中占用的舰船。
2. 从新的准备页截图点击预定槽位。
3. 重置筛选，再使用精确中文名搜索，并结合舰种和国籍筛选。
4. 多个形态或复制人同名时，名字和等级不再是唯一身份。逐一核对显示的舰种、等级、改造形态、可用状态、装备，以及当期攻略实际依赖的技能。
5. 用户通常会把主力标为 `收藏`，所以先检查收藏候选；不得把 `收藏` 与锁定标记混淆。收藏只是一项偏好与定位信号：提交选择前仍要打开详情，核对精确的当前技能分支或名称及等级。若多个候选都收藏或标记看不清，就检查所有合理候选，无法确认时询问，不能猜。
6. 如果选择器只有在做出可逆选择后才能显示技能，先选候选，回到准备页打开舰船详情，在任何出击之前核验技能。技能错误就更换；不能从点中卡片推断核验成功。
7. 选择优先级依次是：要求的当前技能及等级；正确的改造形态与舰种；收藏主力偏好；可用状态。若收藏候选与攻略已经核验的技能要求冲突，技能要求优先，并报告差异。若攻略依赖技能却没有明确技能，先继续研究或询问，再出击。
8. 在新证据上确认最终槽位和技能。检查点应记录足以区分复制人的字段：精确名称、改造形态、舰种、等级、收藏状态、候选数量、预期技能、实测当前技能与等级、当前槽位和证据侧车。
9. 伤损是准备状态，不是身份。常规修理已授权时，修理技能正确的主力，而不是为了省去修理换成无伤但技能错误的复制人。也不能因为候选更健康或在列表中更靠前就选它。

除非已经核验预设的精确内容并且确实要覆盖整支舰队，否则避免批量预设。套用预设、重启恢复或用户手动改队后，重新做复制人身份检查；六个名字一致仍不足以证明舰队正确。每次换船后都捕获新截图，复核新槽位及其技能证据。

## 选择装备

1. 通过已经核验的游戏内路径进入舰船详情；不要把只读装备预览误认为更换界面。
2. 若要更改多个槽位，先保存装备记录。
3. 使用精确名称搜索，并结合装备类型筛选。
4. 确认物品高亮、可用，并且适用于该槽位。
5. 能直接替换飞机时就直接替换，避免无谓的卸下和再次补充。
6. 返回后核验最终装备及索敌、航速、制空或反潜等相关总值。

禁止靠连续长滑动寻找舰船或装备。只有搜索和筛选已把范围明显缩小时，才允许一次短而有证据的滚动。

## 出击前准备

- 逐槽核对舰名、舰种、国籍、顺序、旗舰、装备、形态，以及所有复制人或技能相关舰船的精确技能和等级。
- 核对约束表中的数量、航速、索敌、条件优先级和入口。
- 完成修理与快速补给，包括飞机，并确认没有计划让 `大破` 舰船继续前进。
- 检查船坞、仓库和掉落空间。满船坞或爆仓默认是阻塞；没有用户对具体处置对象或扩建的明确授权时，暂停并询问。
- 舰队的主要输出类型改变后，重新打开战况中心并核验相应增益。

## 战况中心

浏览战况中心和拟定购买顺序是可逆的只读操作；实际购买会消耗有限活动点数。普通燃料、弹药、修理桶资源充足或一般的“资源随便用”不自动包含活动点数。购买前必须取得用户对当前增益方案或预算的明确授权；若用户已经明确授权在本次活动范围内自由购买战况增益，才可在该范围内执行。权限不清时停在购买前询问。改变舰队主要输出类型后，应重新打开战况中心，并按相关舰种或国籍筛选。

获得上述购买授权后，常见优先级：

1. 削弱路线强制经过的强化节点；
2. 主要舰种的伤害、命中与暴击增益；
3. 适用于长路线的国籍减伤或弹药损失保护；
4. 当前敌方配置要求的生存增益；
5. 点数足够且适合时，选择整次出击增伤等可选卡片。

不要只因某个无关增益便宜就购买。对点数不足的费用或选项截图取证，并采用经过权衡的替代方案。

## 出击与自动带路

- 出击前只选择地图入口 `α`、`β` 或同类入口。
- 出发后显示的路线卡解释自动判定，应等待游戏自行完成。
- 绝不能点击 `B`、`E` 或其他地图节点来“选择”路线。
- 随机分支走错时，按攻略的退出重来或撤退说明处理。
- 确定性分支走错时，重新检查旗舰、舰种、数量、航速、索敌和条件优先级。

## 阵型决策

依据当前敌人和之前记录的结果选择阵型。阵型效果与舰队组成有取舍，不存在对所有节点都正确的阵型。

重复失败时记录：

- 地图、节点和敌方构成；
- 敌方阵型；
- 己方阵型；
- 战果评级和剩余敌舰；
- 己方伤损；
- 有效增益与装备；
- 下一项要验证的改动。

诊断卡点时一次只改变一个主要因素。使用完全不变的失败配置反复重打既浪费时间，也会掩盖原因。

## 结算链

每一屏分别处理：

1. 战果评级；
2. 经验；
3. 掉落、解锁或弹窗；
4. 剧情；
5. 补给以及 `前进` 或 `回港`；
6. 首领或地图结算；
7. 章节与活动奖励状态。

点击 `前进` 前检查所有伤损条，遇到 `大破` 必须停止。击败首领后继续到游戏实际更新地图分数或血条、`CLEAR` 标记或解锁，并检查奖励页；一个醒目的 `SS` 不是完成证据。

## 活动题目

- 截取完整题干和全部选项。
- 在当期题库中搜索精确且有区分度的短语。
- 题号和题目顺序不具有权威性。
- 来源冲突时，采用较新且完整的题库，并用另一个独立权威来源交叉核验。
- 点击后核对绿色或正确结果，再更新检查点。

## 完成清单

针对用户要求的每一项，记录屏幕证据：

- 目标首领或地图已通关，以及分数或血条状态；
- 新开放的入口或章节；
- 章节奖励已领取；
- 活动奖励已领取；
- 题目已完成并记录正确结果；
- 用户要求的宝箱已经取得或开启；
- 功勋或成就已经完成并领取；
- 没有未解决的满船坞、爆仓、结算或伤损阻塞。
