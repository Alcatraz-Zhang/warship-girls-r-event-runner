# MuMu ADB 与恢复

在控制模拟器之前，以及任何中断之后，都先阅读本文。

## 为什么只检查 `adb devices` 不够

MuMu 12 可能通过多个串号暴露同一台 Android 虚拟机，例如 `127.0.0.1:<端口>`、动态主机转发端口和 `emulator-*` 别名。反过来，过期串号或另一台 MuMu 实例也可能仍显示为已连接。因此，可用目标必须由身份指纹确认，不能只看 ADB 的 `device` 状态。

随附解析器检查：

- MuMu 虚拟机索引以及可获得时的实时端口；
- ADB 状态，并确认串号只指向本机回环地址；
- Android 启动 ID 和 Android ID；
- 设备型号；
- 游戏包名与 PID；
- 当前恢复到前台的包名与活动名；
- 物理分辨率、覆盖分辨率和旋转方向。

只有通过标准 UUID 格式校验的相同启动 ID 才能把不同串号视为同一虚拟机的别名。启动 ID 缺失或无效时，各串号保持独立；Android ID 和设备型号只作辅助诊断，不能用于合并目标。MuMu 命令行报告的实时端口优先作为规范串号；指定 `<VM索引>` 后只接受明确含该索引的目标组，找不到时立即报错，不会回退到未知索引。若多个不同的虚拟机都符合条件，而 `-VmIndex` 没有唯一指定目标，解析器也会报错，不会猜测。

## 解析器用法

```powershell
# 游戏必须正在运行。
pwsh -NoProfile -File "<仓库目录>\scripts\resolve-mumu-target.ps1" -Action Info -VmIndex <VM索引>

# 只有游戏处于前台时才允许输入。
pwsh -NoProfile -File "<仓库目录>\scripts\resolve-mumu-target.ps1" -Action Info -VmIndex <VM索引> -RequireForeground

# 只用于启动期间发现虚拟机；绝不能用这个宽松模式决定点击。
pwsh -NoProfile -File "<仓库目录>\scripts\resolve-mumu-target.ps1" -Action Info -VmIndex <VM索引> -AllowGameStopped

# Find 只输出规范串号。
pwsh -NoProfile -File "<仓库目录>\scripts\resolve-mumu-target.ps1" -Action Find -VmIndex <VM索引> -RequireForeground
```

可选环境变量：

- `MUMU_HOME`：MuMu Player 12 安装根目录；
- `MUMU_ADB_PATH`：明确指定 `adb.exe`；
- `MUMU_CLI_PATH`：明确指定 `mumu-cli.exe`；
- `MUMU_VM_ROOT`：明确指定虚拟机目录。

显式设置的路径是唯一搜索范围；只要变量非空但路径无效，解析器就会报错，不会回退到固定安装目录、运行中进程或 `PATH`。

## 截图证据

使用取证脚本，不要反复覆盖 `current.png`：

```powershell
pwsh -NoProfile -File "<仓库目录>\scripts\capture-mumu-state.ps1" `
  -VmIndex <VM索引> `
  -OutputDirectory "<会话证据目录>" `
  -RequireForeground
```

脚本会写入：

- 一张带唯一时间戳和随机标识的 PNG；
- 一个同名 `.json` 侧车；
- 图像宽高和 SHA-256；
- 截图前、截图后的目标指纹，包括前台包名和 Activity。

若截图过程中前台 Activity 或任一其他指纹字段发生变化，就把截图视为不稳定证据，不能据此点击。侧车中的捕获时间在截图开始前固定，不会因截图、哈希或第二次目标解析耗时而向后漂移。

## 证据绑定输入

```powershell
pwsh -NoProfile -File "<仓库目录>\scripts\send-mumu-input.ps1" `
  -Action Tap -X <横坐标> -Y <纵坐标> `
  -EvidenceJson "<新侧车文件>"
```

可用动作是 `Tap`、`Swipe` 和 `KeyEvent`。`KeyEvent` 仅允许 `66`（Enter）、`67`（Del）、`112`（ForwardDel）和 `279`（Paste）；包括返回键和 `280` 及以上系统导航键在内的其他键码全部拒绝。四个白名单键也只能依据当前新证据使用；其中 `279` 仅用于已经核验为可见且已聚焦的游戏内文本框，并且发送前必须确认剪贴板内容。每张新截图只执行一个动作。短滑动可用于已经核验的页面过渡，但不能用于在舰船或装备长列表中盲目搜索。

当实时指纹（包括前台 Activity）与侧车不一致、截图缺失或被修改、证据过旧，或者缺少动作所需坐标时，脚本拒绝输入。脚本以原子方式建立 `.consumed.json` 回执，因此同一侧车不能驱动第二次输入。即使发生错误也要保留回执，因为 ADB 可能已经部分执行；应重新截图，不能删除回执或绕过检查。

## 恢复决策表

| 触发条件 | 立即动作 | 恢复规则 |
|---|---|---|
| 电脑或 MuMu 重启 | 废弃串号与截图，重新解析虚拟机，等待 Android 和游戏可用 | 从新截图观察到的页面重新进入流程 |
| 图形驱动或游戏崩溃 | 停止输入，重新解析并截图 | 若游戏回到首页或登录页，重新进入活动并先检查进度，再决定是否重打 |
| 用户说截图与实际画面不同 | 立即停止，不得用“延迟”解释后继续 | 重新解析，核对前台与指纹，创建唯一的新截图 |
| ADB 命令超时或报错 | 假定命令可能已部分执行 | 任何重试前先重新解析并截图 |
| 用户手动导航 | 使全部坐标和页面假设失效 | 截图并重新分类新页面 |
| 旧视图显示战斗，用户说已到结算 | 停止输入 | 由新截图决定等待、继续结算或返回地图 |
| 多个虚拟机匹配 | 不得猜测 | 请用户确认 `VmIndex`，并将确认后的索引写入检查点 |
| 游戏退到后台 | 不得点击 | 通过明确且可核验的启动或恢复动作把游戏带回前台 |

## 坐标规则

- Unity 常常只暴露一个 `SurfaceView`，界面树可能没有文字。以唯一的新截图作为页面分类的主要证据。
- `wm size` 可能报告竖屏 `1440x2560`，而游戏截图是横屏 `2560x1440`。坐标空间以截图实际宽高和旋转方向为准。
- 每次点击都从当前页面可见锚点推导。不得把固定坐标带到其他分辨率、旋转、虚拟机或页面。
- 绝不发送 Android 返回键或其他系统导航键。只使用新截图中可见的游戏内返回箭头、关闭按钮或其他明确控件。

## 轮询页面过渡

普通动画和加载期间，每隔约 1 至 5 秒捕获一张新截图进行轮询；较长战斗中持续给出简短进度。不要固定盲等很长时间后假定已经到某一页，因为战斗可能早已进入结算，也可能出现意外弹窗。
